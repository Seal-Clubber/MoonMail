# Your wallet-controlled mailbox

My inbox gives each owned Sapient postbox a full-width mail workspace with a folder sidebar, searchable letter list and reading pane. A compact toolbar keeps postbox selection, refresh and editing near the top; address details sit below the mail. Desktop folders, message rows and reading pane scroll independently. It uses the existing on-chain post office; there is no GhostDrop account server or mailbox database.

## What follows you to another device

Reconnect the same Sapient wallet to the same post office, select your postbox and approve the private view permission. The postbox identity, encrypted letters, recovery capsules, original gift amounts and collected flags come from Ootle. Nothing needs to be exported from the previous browser to recover these records. The wallet must still control the postbox and retain access to its recovery outputs. Browsing a different network or registry opens a different post office.

Inbox includes loaded letters addressed to that postbox and controller. Available gifts and Collected gifts filter those letters by their on-chain gift state. These folders are derived views, so the same loaded chain state produces the same contents on another device. Counts always describe loaded letters; use Load more letters when the post office has another page. Post office order is registry order, not a fabricated delivery timestamp.

Sent includes loaded on-chain letters whose sender is the postbox controller and whose verified reply postbox is this postbox. Letters without that reply address cannot be assigned to a particular sending postbox. Public sent mail can be read. New private postbox and private-link letters can include a separately encrypted sender copy inside the same on-chain letter. Writing from My inbox selects your sending postbox and enables Save an encrypted copy in Sent by default. Review shows whether the copy is included. In Sent, approve private view access and unlock loaded letters to search and read their subjects and bodies. Reconnect the same Sapient wallet on another device to recover those copies from the permanent capsule recorded with each letter, including historical key versions. Older letters without a saved sender copy keep their delivery details; their plaintext cannot be recreated. Private-link copies contain the message, not the original secret URL or claim key. Collected flags alone do not prove who received a payout.

## Reading and writing

On a reload in the same browser tab, GhostDrop tries to restore a connection you previously approved, using Sapient's read-only account API. A nonsecret tab-session reminder contains only the network number; it is not wallet permission. A locked wallet, removed site grant or changed account/network requires reconnecting. Disconnect removes the reminder and clears private session state. On inbox or setup entry, GhostDrop asks Sapient whether the current account already grants private view access. An existing grant is reused without a repeat prompt. If permission is missing, GhostDrop explains private view access in a guided dialog. Choose Continue in Sapient to request permission and approve it in your wallet. Opening the dialog alone requests nothing. Not now (or Escape) leaves your inbox locked with an Unlock private inbox button; the explanation does not repeatedly interrupt the same connected account. A declined request stays in the dialog with a retry option. Setup still requires two separate transaction approvals after permission. The existing permission covers the connected account's private output summaries, including other amounts and memos; it does not expose seed or signing keys. Unlocking reads existing recovery state and decrypts loaded letters. It sends no transaction. Subjects and body previews stay in application memory for the wallet session, and are cleared on disconnect, account change or post office change. They are not written to localStorage, sessionStorage or the delivery journal. Another device decrypts its own copy after permission approval.

Search matches public IDs, sender/routing keys and the subjects and bodies unlocked in the current session. It cannot search ciphertext. Sort by registry order, unlocked subject or original gift amount. Lists show twelve matching letters per page.

Compose letter opens the existing writing desk with this postbox selected for replies and its controlling funding account. An existing unfinished draft is preserved. Review the recipient, visibility, gift and fees before sending. Including a reply address exposes that postbox ID on chain. Opening an incoming letter uses the existing retry, reply and gift-review controls in the reading pane. Public letters and private-link gifts retain their existing guest reader.

## Privacy and scope

Encryption protects sealed subjects and messages. Revealed test TARI amounts, sender/controller keys, routing, transaction timing and reply postbox IDs remain observable. This is Esmeralda testnet mail, with the existing indexer trust model; it is not SMTP/IMAP email and cannot send to Gmail, Proton or Outlook addresses.

The new [single-template post office](unified-contract.md) stores encrypted read/star/archive marks, sorting and message spacing on Ootle. Opening a successfully decrypted received letter automatically stages its read mark. Unlocking list previews alone leaves letters unread. Select individual letters or the current page, then use the action menu to mark read/unread, star/unstar, archive or move back to Inbox; there are no read/archive buttons on individual rows. Unread rows have a bright blue edge, bold subject and an explicit Unread label. A prominent gold save reminder appears whenever settings change. Choose Save mailbox changes and approve one transaction in Sapient; unsaved edits stay in memory across inbox/composer navigation. Discard restores the loaded snapshot. Supported browsers warn before a reload or close loses unsaved settings, and other app pages retain a return-to-inbox reminder. On another device, connect the same wallet and approve private view access if needed; mailbox settings load automatically from Ootle. Failed or damaged settings remain locked with an explicit retry, never an empty editable replacement. A stale save is rejected without overwriting the saved snapshot; discard unsaved changes and reload before saving again. Archive hides mail from Inbox but cannot delete immutable chain data. These settings do not publish read receipts. Favourite postbox IDs are encrypted with the other settings. Device-only persistent preferences are not introduced. The existing browser delivery journal remains necessary for safe reconciliation of uncertain signing/transaction requests; it is not the authority for on-chain mail or gifts. It does not automatically move to a new browser.

## Verification

[Mailbox verification evidence](chain-mailbox-evidence.json) separates synthetic browser regressions from real Esmeralda acceptance. The real checks use the existing isolated restored stock Sapient wallet and existing on-chain letters, with signing/broadcast methods blocked. All six addressed campaign letters opened in the new reading pane; the mailbox, search and reading worked at 390 px and 320 px. The real 33-letter public hall and two private-link readers also passed. This verifies the local production build against the real network, not a newly published Pages deployment.

The unified-contract campaign separately confirmed fifteen real Esmeralda transactions, including long letters, saved encrypted preferences, key rotation and a full gift-funded payout to an empty restored Sapient account. Read-only actual UI checks recovered archive/star/layout settings and historical private mail at 1440, 390 and 320 px. [Unified acceptance evidence](unified-contract-evidence.json) records this new office and distinguishes chain deployment from the website awaiting the user’s push.

Sent copies are separate AES-GCM ciphertext bound to the office, original letter, primary payload, sender and routing. They do not grant access to the recipient’s wallet or change gift ownership. The same publication stores both copies, so sending requires the existing single Sapient transaction approval. Copies consume additional space within the existing 32 KiB component limit and the editor includes that overhead in its budget. The original recipient ciphertext is preserved. Sent plaintext stays in a separate session-memory map and is cleared with the wallet/office session. This client protocol uses the existing unified contract’s opaque JSON payload; no contract replacement or automatic history migration is needed.

Mailbox settings also save up to 128 favourite postbox IDs, encrypted with the same recovery capsule. Older saved settings load with no favourites. Contacts live at the writing desk, next to recipient selection. They show favourites, verified previous correspondents from loaded mail, then listed postboxes. Favourites use the sending postbox's encrypted settings and the same visible save reminder. Names are not unique; check IDs. Selection applies read/unread, star/unstar and archive/inbox actions to multiple received messages. Actions are staged in memory; one approved mailbox save persists the batch on Ootle. Discard restores the loaded snapshot. No drafts are saved.

Reply conversations use optional `gd-thread-1` parent/root IDs inside the encrypted letter and its encrypted Sent copy. The app joins only direct decrypted reply links between the same verified pair of postboxes. It never groups by subject alone. Missing/locked messages remain outside the loaded conversation; unlock Inbox and Sent and load more mail for a fuller view. Cycles, malformed metadata and different correspondents do not join. Parent-first ordering reflects reply relationships; the app does not invent email timestamps or read receipts. Old mail can start new threads when replied to; encrypted thread metadata adds to the existing32KiB combined payload limit.

The new email controls were verified separately on real Esmeralda with unmodified stock Sapient0.6.6. Three giftless publications and one encrypted settings save committed; actual combined fees were 0.045547 test TARI. An independently restored wallet profile recovered addressed/link Sent, a two-message self-addressed reply conversation, bulk read/star marks and its favourite at mailbox revision4. Cross-correspondent thread isolation is additionally covered by cryptographic/client/browser tests. The test used reviewed local static assets on the Pages HTTPS origin with real indexer responses. See [sanitized email acceptance evidence](email-mailbox-evidence.json); the agent did not push or publish this frontend.

The automatic settings, selected-letter action menu, unread contrast, composer contacts and permission reuse have browser regression coverage on desktop and mobile with encrypted Sapient/Ootle fixtures. Passive resume and grant queries have SDK unit coverage, including missing grants and account changes. These checks do not broadcast or constitute a new live stock-wallet acceptance; the previous real Esmeralda acceptance remains the evidence for the unchanged settings contract.
